# Part 1 — Identify an instance, not just a number

A PID can be reused after a process exits. A command name can also match several unrelated tasks. Before acting on a candidate, verify the machine, boot, PID, start time, owner, parent and full command. An old PID file is a clue, not permission to kill that number.

This lab never asks you to terminate an arbitrary process. Your optional demonstration child is a short sleeping Python process that exits naturally. Your analyzer does not signal anything.

Within the supplied schema, identity is boot label, PID and start ticks. That is sufficient for the specific comparison contract, not a universal identity mechanism across machines. The host provenance remains in your collection notes.

# Part 2 — Inspect a harmless child and let it exit

In your Bash workspace shell, start a three-second child:


After `wait`, do not send a signal to the old number. A later process may reuse it. Your shell reaps this child, so it does not leave a persistent background worker.

# Part 3 — Read process state with its limits

| State | What the snapshot suggests | What it does not establish |
| --- | --- | --- |
| R | Running or runnable | That it consumed a full CPU throughout your interval |
| S | Interruptible sleep | That it is broken or idle forever |
| D | Uninterruptible wait | The specific device or cause of the wait |
| Z | Exited child awaiting reaping | A running process you can fix with a CPU kill |
| T / t | Stopped or tracing stop | Why that state was requested |

Read your Linux VM's process views:

```bash
ps -eo pid,ppid,user,lstart,stat,comm --sort=pid | head -n 15
ps -eo pid,pcpu,rss,comm --sort=-pcpu | head -n 10
```

RSS is resident physical memory associated with the process view; summing RSS across processes can double-count shared pages. An executable name and a low CPU percentage do not prove that its request path is healthy.

# Part 4 — Understand the interval calculation

Linux process CPU counters use clock ticks; obtain the tick rate with `getconf CLK_TCK` or `os.sysconf('SC_CLK_TCK')`, not a hardcoded assumption. The supplied tool divides the CPU-tick delta by tick rate and actual elapsed seconds.

Its percentage is normalized to one logical CPU. A multi-threaded process can legitimately exceed 100%. That result means more than one CPU worth of accounted execution in the interval, not an impossible arithmetic error.

The normal fixture increases by 50 ticks at 100 ticks per second over two seconds: 25% of one CPU. The tool marks 100% or more, or a D/Z state, as a reason to inspect further. Those are teaching attention conditions, not proof of customer impact.

# Part 7 — Design the final tool before typing it

Your tool accepts one JSON evidence file. It reads at most 1 MiB, rejects malformed JSON, duplicate keys, nonfinite numbers, directories and final-component symbolic links, and validates the domain fields before printing a report. It never evaluates the input as shell or Python code.

| Exit status | Meaning |
| --- | --- |
| 0 | The documented analysis completed and its success criterion is met |
| 1 | Valid evidence requires attention, or the available evidence cannot establish the required outcome |

The file checks assume your private workspace is trusted. They are not race-proof protection against a malicious writer changing parent directories or files during a read. Do not expose the tool as a privileged service or point it at hostile paths.

<!-- lab:implementation -->
```bash
cat > scripts/process-interval.py <<'PY'
#!/usr/bin/env python3
"""Process Monitoring — bounded evidence analysis for this lab."""
import argparse
import datetime as dt
import json
import math
from pathlib import Path
import stat
import sys


def integer(value, name, low=0, high=10**18):
    if type(value) is not int or not low <= value <= high:
        raise ValueError(name + ': expected an integer in the documented range')
    return value


def number(value, name, low=0, high=10**12):
    if type(value) not in (int, float) or not math.isfinite(value) or not low <= value <= high:
        raise ValueError(name + ': expected a finite number in the documented range')
    return value


def text(value, name):
    if not isinstance(value, str) or not value.strip() or len(value) > 1000:
        raise ValueError(name + ': expected nonempty bounded text')
    if any(ord(c) < 32 or ord(c) == 127 for c in value):
        raise ValueError(name + ': control characters are not allowed')
    return value


def fields(obj, names):
    if not isinstance(obj, dict) or set(obj) != set(names.split()):
        raise ValueError('expected exactly these fields: ' + names)


def reject_duplicates(pairs):
    result = {}
    for key, value in pairs:
        if key in result:
            raise ValueError('duplicate JSON key')
        result[key] = value
    return result


def load(path):
    # A private, trusted lab workspace is a prerequisite, not a hostile-directory sandbox.
    if path.is_symlink() or not stat.S_ISREG(path.stat().st_mode):
        raise ValueError('input must be a regular non-symlink file')
    with path.open('rb') as stream:
        data = stream.read(1024 * 1024 + 1)
    if len(data) > 1024 * 1024:
        raise ValueError('input exceeds the 1 MiB lab limit')
    return json.loads(data.decode('utf-8'), object_pairs_hook=reject_duplicates,
                      parse_constant=lambda _: (_ for _ in ()).throw(ValueError('nonfinite JSON value')))


def analyze(doc):
    fields(doc, 'before after ticks_per_second elapsed_seconds')
    hz = integer(doc['ticks_per_second'], 'ticks_per_second', 1, 1000000)
    elapsed = number(doc['elapsed_seconds'], 'elapsed_seconds', 0.001, 300)
    for key in ('before', 'after'):
        sample = doc[key]
        if sample is None and key == 'after':
            continue
        fields(sample, 'boot pid start_ticks cpu_ticks state')
        text(sample['boot'], 'boot')
        integer(sample['pid'], 'pid', 1)
        integer(sample['start_ticks'], 'start_ticks')
        integer(sample['cpu_ticks'], 'cpu_ticks')
        if sample['state'] not in ('R', 'S', 'D', 'Z', 'T', 't', 'I', 'X'):
            raise ValueError('unsupported process state')
    old, new = doc['before'], doc['after']
    identity = ('boot', 'pid', 'start_ticks')
    if new is None or any(old[k] != new[k] for k in identity):
        return 1, {'interval': 'unavailable', 'one_cpu_percent': None,
                   'reason': 'process exited or identity changed'}
    delta = new['cpu_ticks'] - old['cpu_ticks']
    if delta < 0:
        raise ValueError('CPU counter regression for comparable identity')
    percent = round(100 * delta / hz / elapsed, 2)
    return int(percent >= 100 or new['state'] in ('D', 'Z')), {
        'interval': 'comparable', 'one_cpu_percent': percent,
        'state': new['state'], 'readiness': 'not measured'}


def main():
    parser = argparse.ArgumentParser(description=__doc__)
    parser.add_argument('input', type=Path, help='private lab JSON evidence file; never executed as code')
    args = parser.parse_args()
    try:
        status, report = analyze(load(args.input))
        print(json.dumps(report, sort_keys=True, indent=2, allow_nan=False))
        return status
    except (OSError, ValueError, TypeError, KeyError, OverflowError, RecursionError) as error:
        print('ERROR: ' + str(error), file=sys.stderr)
        return 2


if __name__ == '__main__':
    sys.exit(main())
PY
```

## Explain the implementation

`fields` rejects missing and unexpected object fields so a misspelling cannot silently become an absent observation. `integer` rejects booleans as numeric counters. `number` rejects nonfinite values. Those checks are deliberate: Python otherwise treats `True` as an integer, and permissive JSON parsers may accept nonstandard numeric constants.

`load` bounds the input size before decoding it and rejects duplicate keys. The `analyze` function contains your subject-specific decisions; walk through it with the supplied numbers and predict the report before running it. `main` prints JSON rather than terminal control sequences and keeps errors on stderr. It does not open a second evidence file, invoke a repair command or change host policy.

Your program has no execute permission requirement because you invoke it explicitly with `python3`. That keeps the interpreter choice visible. Do not run it as root merely because an input is inaccessible.

# Part 10 — Create and run your regression suite

The tests launch the actual CLI in fresh subprocesses, compare selected report fields and check meaningful nonzero statuses. They also reject malformed, duplicate-key, nonfinite, missing, oversized, directory and symbolic-link inputs. Test fixtures are private and removed after the run.

```bash
cat > tests/run-tests.py <<'PY'
#!/usr/bin/env python3
"""Run the documented fixture checks without inspecting or changing a host."""
import json
from pathlib import Path
import subprocess
import sys
import tempfile

ROOT = Path(__file__).resolve().parents[1]
TOOL = ROOT / 'scripts' / 'process-interval.py'
CASES = [('normal process interval', {'before': {'boot': 'boot-a', 'pid': 1234, 'start_ticks': 500, 'cpu_ticks': 100, 'state': 'S'}, 'after': {'boot': 'boot-a', 'pid': 1234, 'start_ticks': 500, 'cpu_ticks': 150, 'state': 'S'}, 'ticks_per_second': 100, 'elapsed_seconds': 2}, 0, {'one_cpu_percent': 25.0, 'readiness': 'not measured'}), ('multiple CPU execution', {'before': {'boot': 'boot-a', 'pid': 1234, 'start_ticks': 500, 'cpu_ticks': 100, 'state': 'S'}, 'after': {'boot': 'boot-a', 'pid': 1234, 'start_ticks': 500, 'cpu_ticks': 600, 'state': 'S'}, 'ticks_per_second': 100, 'elapsed_seconds': 2}, 1, {'one_cpu_percent': 250.0}), ('PID reused', {'before': {'boot': 'boot-a', 'pid': 1234, 'start_ticks': 500, 'cpu_ticks': 100, 'state': 'S'}, 'after': {'boot': 'boot-a', 'pid': 1234, 'start_ticks': 501, 'cpu_ticks': 150, 'state': 'S'}, 'ticks_per_second': 100, 'elapsed_seconds': 2}, 1, {'interval': 'unavailable', 'one_cpu_percent': None}), ('process exited', {'before': {'boot': 'boot-a', 'pid': 1234, 'start_ticks': 500, 'cpu_ticks': 100, 'state': 'S'}, 'after': None, 'ticks_per_second': 100, 'elapsed_seconds': 2}, 1, {'interval': 'unavailable'}), ('counter regression', {'before': {'boot': 'boot-a', 'pid': 1234, 'start_ticks': 500, 'cpu_ticks': 100, 'state': 'S'}, 'after': {'boot': 'boot-a', 'pid': 1234, 'start_ticks': 500, 'cpu_ticks': 99, 'state': 'S'}, 'ticks_per_second': 100, 'elapsed_seconds': 2}, 2, {}), ('zero tick frequency', {'before': {'boot': 'boot-a', 'pid': 1234, 'start_ticks': 500, 'cpu_ticks': 100, 'state': 'S'}, 'after': {'boot': 'boot-a', 'pid': 1234, 'start_ticks': 500, 'cpu_ticks': 150, 'state': 'S'}, 'ticks_per_second': 0, 'elapsed_seconds': 2}, 2, {})]


def run(path):
    return subprocess.run([sys.executable, str(TOOL), str(path)],
                          capture_output=True, text=True, timeout=10)


def check(condition, message):
    if not condition:
        raise AssertionError(message)


count = 0
with tempfile.TemporaryDirectory(prefix='regression-', dir=ROOT / 'fixtures') as temp:
    folder = Path(temp)
    for name, document, status, expected in CASES:
        path = folder / 'case.json'
        path.write_text(json.dumps(document), encoding='utf-8')
        result = run(path)
        check(result.returncode == status, name + ': status: ' + result.stderr + result.stdout)
        if status != 2:
            report = json.loads(result.stdout)
            for key, value in expected.items():
                check(report.get(key) == value, name + ': unexpected ' + key + ': ' + result.stdout)
        else:
            check(not result.stdout and result.stderr.startswith('ERROR:'), name + ': error contract')
        print('PASS ' + name)
        count += 1
    for name, payload in [('bad-json', '{'), ('duplicate-key', '{"x":1,"x":2}'),
                          ('nonfinite', '{"x":NaN}'), ('invalid-utf8', b'\xff')]:
        path = folder / 'invalid.json'
        path.write_bytes(payload if isinstance(payload, bytes) else payload.encode('utf-8'))
        result = run(path)
        check(result.returncode == 2 and not result.stdout, name)
        print('PASS ' + name)
        count += 1
    missing = folder / 'missing.json'
    check(run(missing).returncode == 2, 'missing input')
    count += 1
    target = folder / 'target.json'
    target.write_text('{}', encoding='utf-8')
    link = folder / 'link.json'
    link.symlink_to(target)
    check(run(link).returncode == 2, 'symlink input')
    count += 1
    large = folder / 'large.json'
    large.write_bytes(b' ' * (1024 * 1024 + 1))
    check(run(large).returncode == 2, 'oversized input')
    count += 1
    check(run(folder).returncode == 2, 'directory input')
    count += 1
print('PASS: %s assertions; temporary test fixtures removed' % count)
PY
```

# Part 15 — Knowledge assessment

Answer these before reading the explanation. Demonstrate the answers with your own evidence where appropriate.

## 1. Why is a PID insufficient identity?

The kernel can reuse it after exit, so different instances can share the same number.

## 2. Why retain boot and start ticks?

They detect a changed instance within the declared host collection boundary before counter subtraction.

## 3. What does 250% mean here?

Two and a half CPUs worth of accounted execution over the interval under one-CPU normalization.

## 4. Why query clock ticks?

The counter unit must come from the target rather than a fixed guessed frequency.

## 5. Can a sleeping process be healthy?

Yes. Waiting for work is common; process state alone does not determine application readiness.

## 6. Can you kill a zombie to repair it?

It has exited; reaping and parent behavior are the relevant observations, not CPU termination.

## 7. Why not split /proc/PID/stat blindly on spaces?

The comm field can contain spaces and parentheses; the numeric tail needs correct boundary handling.

## 8. Why can RSS sums mislead?

Shared resident pages can appear in several process views.

## 9. What does an exited second sample report?

An unavailable interval, not fabricated zero use.

## 10. How do you clean up the demonstration child?

It has a three-second lifetime and you wait for that exact child; you do not reuse its stale PID for signaling.
