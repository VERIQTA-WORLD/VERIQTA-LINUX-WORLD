# Part 1 — Keep the layers distinct

Your interface can be up while the service is bound to the wrong address. A route can exist while a firewall drops a flow. A TCP connection can succeed while HTTP returns the wrong content. Monitor the layer that matches the user's complaint.

| Observation | Useful conclusion | Limit |
| --- | --- | --- |
| Interface state/address | The local interface has the displayed configuration | Not proof of a working remote path |
| Route lookup | The local routing decision for a destination | Not proof that the packet arrived |
| Listening socket | A local endpoint is listening | Not proof of client reachability or application readiness |
| Interface byte delta | Accounted aggregate traffic changed | Not proof that a particular request succeeded |
| Application acceptance | A specific operation returned the expected result | Limited to that operation, client and observation window |

Keep these observations separate in your notes. JUN-083 will use a local application path to investigate connectivity; this lab concentrates on monitoring rather than route repair.

# Part 3 — Read counters as cumulative evidence

An interface's byte counters accumulate. Subtract two snapshots of the same interface instance, then divide by actual monotonic elapsed seconds. The lab reports bytes per second, not bits per second; multiply by eight only when converting explicitly.

Error/drop counters are supporting clues. A drop at one interface does not identify a faulty cable, saturated application or remote firewall. Compare interval deltas rather than lifetime totals accumulated since boot.

The tool records a supplied namespace label plus interface index and name. The label is your provenance, not an automatically verified namespace identity. Interface index/name checks detect some collection changes, but cannot prove there was no deletion/recreation or counter reset between observations. A regressing counter is rejected; a hidden reset followed by growth remains an important limitation.

# Part 5 — Calculate the supplied rates and boundaries

The normal fixture adds 2000 receive bytes and 1000 transmit bytes over two seconds. Expect 1000 receive bytes/s and 500 transmit bytes/s. No new errors or drops are recorded in that interval.

The attention rule is any positive error/drop delta. It intentionally prompts investigation rather than specifying an acceptable production error budget. A candidate with one new receive drop should return attention even if the rate remains high. Throughput and correctness are different observations.

When the interface identity changes or a counter decreases, the pair is invalid for this calculation. You should collect a new interval, not take the absolute value of the delta.

# Part 7 — Design the final tool before typing it

Your tool accepts one JSON evidence file. It reads at most 1 MiB, rejects malformed JSON, duplicate keys, nonfinite numbers, directories and final-component symbolic links, and validates the domain fields before printing a report. It never evaluates the input as shell or Python code.

| Exit status | Meaning |
| --- | --- |
| 0 | The documented analysis completed and its success criterion is met |
| 1 | Valid evidence requires attention, or the available evidence cannot establish the required outcome |
| 2 | Input, schema, range, collection or usage error; no normal report is printed |

A zero result concerns this tool's stated contract, not whole-system health. An attention result is different from malformed input. Your shell's status must be captured immediately after the command, before another command replaces it.

The analyzer verifies each identity and nonnegative counter, reports byte rates and new error/drop events, and deliberately leaves application health unmeasured. All counters must describe one declared interface scope.

The file checks assume your private workspace is trusted. They are not race-proof protection against a malicious writer changing parent directories or files during a read. Do not expose the tool as a privileged service or point it at hostile paths.

```bash
cat > scripts/network-interval.py <<'PY'
#!/usr/bin/env python3
"""Basic Network Monitoring — bounded evidence analysis for this lab."""
import argparse
import datetime as dt
import json
import math
from pathlib import Path
import stat
import sys


def integer(value, name, low=0, high=10**18):
    if type(value) is not int or not low <= value <= high:
        raise ValueError(name + ': expected an integer in the documented range')
    return value


def number(value, name, low=0, high=10**12):
    if type(value) not in (int, float) or not math.isfinite(value) or not low <= value <= high:
        raise ValueError(name + ': expected a finite number in the documented range')
    return value


def text(value, name):
    if not isinstance(value, str) or not value.strip() or len(value) > 1000:
        raise ValueError(name + ': expected nonempty bounded text')
    if any(ord(c) < 32 or ord(c) == 127 for c in value):
        raise ValueError(name + ': control characters are not allowed')
    return value


def fields(obj, names):
    if not isinstance(obj, dict) or set(obj) != set(names.split()):
        raise ValueError('expected exactly these fields: ' + names)


def reject_duplicates(pairs):
    result = {}
    for key, value in pairs:
        if key in result:
            raise ValueError('duplicate JSON key')
        result[key] = value
    return result


def load(path):
    # A private, trusted lab workspace is a prerequisite, not a hostile-directory sandbox.
    if path.is_symlink() or not stat.S_ISREG(path.stat().st_mode):
        raise ValueError('input must be a regular non-symlink file')
    with path.open('rb') as stream:
        data = stream.read(1024 * 1024 + 1)
    if len(data) > 1024 * 1024:
        raise ValueError('input exceeds the 1 MiB lab limit')
    return json.loads(data.decode('utf-8'), object_pairs_hook=reject_duplicates,
                      parse_constant=lambda _: (_ for _ in ()).throw(ValueError('nonfinite JSON value')))


def analyze(doc):
    fields(doc, 'scope before after elapsed_seconds')
    text(doc['scope'], 'scope')
    elapsed = number(doc['elapsed_seconds'], 'elapsed_seconds', 0.001, 300)
    keys = ('rx_bytes', 'tx_bytes', 'rx_errors', 'tx_errors', 'rx_dropped', 'tx_dropped')
    for side in ('before', 'after'):
        item = doc[side]
        fields(item, 'ifindex name ' + ' '.join(keys))
        integer(item['ifindex'], 'ifindex', 1)
        text(item['name'], 'name')
        for key in keys:
            integer(item[key], key)
    old, new = doc['before'], doc['after']
    if (old['ifindex'], old['name']) != (new['ifindex'], new['name']):
        raise ValueError('interface identity changed; collect a new pair')
    delta = {key: new[key] - old[key] for key in keys}
    if any(value < 0 for value in delta.values()):
        raise ValueError('counter regression; pair not comparable')
    events = sum(delta[key] for key in keys[2:])
    return int(events > 0), {'rx_bytes_per_second': round(delta['rx_bytes'] / elapsed, 2),
                            'tx_bytes_per_second': round(delta['tx_bytes'] / elapsed, 2),
                            'error_drop_events': events, 'scope': doc['scope'],
                            'application_health': 'not measured'}


def main():
    parser = argparse.ArgumentParser(description=__doc__)
    parser.add_argument('input', type=Path, help='private lab JSON evidence file; never executed as code')
    args = parser.parse_args()
    try:
        status, report = analyze(load(args.input))
        print(json.dumps(report, sort_keys=True, indent=2, allow_nan=False))
        return status
    except (OSError, ValueError, TypeError, KeyError, OverflowError, RecursionError) as error:
        print('ERROR: ' + str(error), file=sys.stderr)
        return 2


if __name__ == '__main__':
    sys.exit(main())
PY
```

## Explain the implementation

`fields` rejects missing and unexpected object fields so a misspelling cannot silently become an absent observation. `integer` rejects booleans as numeric counters. `number` rejects nonfinite values. Those checks are deliberate: Python otherwise treats `True` as an integer, and permissive JSON parsers may accept nonstandard numeric constants.

`load` bounds the input size before decoding it and rejects duplicate keys. The `analyze` function contains your subject-specific decisions; walk through it with the supplied numbers and predict the report before running it. `main` prints JSON rather than terminal control sequences and keeps errors on stderr. It does not open a second evidence file, invoke a repair command or change host policy.

Your program has no execute permission requirement because you invoke it explicitly with `python3`. That keeps the interpreter choice visible. Do not run it as root merely because an input is inaccessible.

# Part 15 — Knowledge assessment

Answer these before reading the explanation. Demonstrate the answers with your own evidence where appropriate.

## 1. Does byte growth prove your client request worked?

No. It is aggregate traffic at a particular interface, not an application acceptance result.

## 2. Why retain namespace scope?

Interfaces and routes are interpreted within a network namespace, so the same name can describe different boundaries.

## 3. What does ss -lnt select?

Listening TCP sockets with numeric addresses and ports.

## 4. Why inspect IPv6 as well?

A service may bind or route differently across families, and a single IPv4 view is incomplete.

## 5. Why use monotonic elapsed time?

It measures the actual sample duration without wall-clock adjustments changing the rate denominator.

## 6. How do bytes/s differ from bits/s?

One byte contains eight bits; labels and conversions must be explicit.

## 7. Does one receive drop identify the cause?

No. It is a clue requiring scope-specific evidence, not a complete causal diagnosis.

## 8. Why reject a changed ifindex?

The snapshots may describe different interface instances and cannot safely support a delta.

## 9. Can nondecreasing counters rule out every reset?

No. A reset followed by enough new traffic can be hidden between samples.

## 10. Why is a quiet interval valid?

Zero measured delta is a real observation, unlike a missing sample converted into zero.
