# Part 1 — Understand what your CPU measurement measures

CPU utilization describes time accounted to CPU states over a particular interval. Load average describes a different quantity: runnable tasks and tasks in uninterruptible sleep averaged over time. It is not a percentage, and a high load does not independently prove CPU execution saturation.

A host with four logical CPUs can run several threads concurrently. A process view normalized to one CPU can exceed 100% for a multithreaded process; an aggregate host view usually uses all accounted CPU time as its denominator. Name your denominator before comparing graphs.

Write down the question you need to answer: is the application delayed by execution competition, blocked I/O, hypervisor scheduling, or something not yet measured? Each alternative needs different supporting evidence.

# Part 3 — Read the cumulative CPU line

The aggregate `cpu` line in `/proc/stat` accounts time in user, nice, system, idle, iowait, irq, softirq and steal states, followed by guest fields on supported kernels. Values accumulate; one snapshot cannot establish an interval percentage.

This lab accepts exactly the first eight counters in that order. Guest and guest_nice time are already included in their corresponding user/nice accounting, so you must not add the guest fields again. The tool computes deltas, sums the eight deltas and divides each selected category by that interval total.

Your execution percentage includes user, nice, system, irq and softirq deltas. Idle, iowait and steal are reported separately. I/O wait accounting has limitations and can decrease in real observations; this teaching tool rejects any regressing counter rather than manufacturing a percentage. CPU hotplug, resets or collection changes need a fresh comparable pair.

# Part 5 — Calculate the supplied result by hand

The normal pair increases by `[30, 0, 20, 130, 10, 0, 0, 10]`. Total accounted time is 200 ticks. Execution is 50 ticks, so it represents 25%; idle is 65%; I/O wait is 5%; steal is 5%.

A 25% aggregate execution result on a four-CPU host does not prove a single-threaded application has spare execution capacity. One thread could be fully busy while other CPUs are idle. Correlate per-thread data, workload latency and the observation interval before recommending more CPUs.

The attention threshold in this exercise is execution at or above 80%. It is a teaching threshold, not a universal alert rule. Steal and I/O wait remain separate evidence even when that threshold is not met.

# Part 7 — Design the final tool before typing it

Your tool accepts one JSON evidence file. It reads at most 1 MiB, rejects malformed JSON, duplicate keys, nonfinite numbers, directories and final-component symbolic links, and validates the domain fields before printing a report. It never evaluates the input as shell or Python code.

| Exit status | Meaning |
| --- | --- |
| 0 | The documented analysis completed and its success criterion is met |
| 1 | Valid evidence requires attention, or the available evidence cannot establish the required outcome |
| 2 | Input, schema, range, collection or usage error; no normal report is printed |

A zero result concerns this tool's stated contract, not whole-system health. An attention result is different from malformed input. Your shell's status must be captured immediately after the command, before another command replaces it.

The file checks assume your private workspace is trusted. They are not race-proof protection against a malicious writer changing parent directories or files during a read. Do not expose the tool as a privileged service or point it at hostile paths.

```bash
cat > scripts/cpu-interval.py <<'PY'
#!/usr/bin/env python3
"""Basic CPU Monitoring — bounded evidence analysis for this lab."""
import argparse
import datetime as dt
import json
import math
from pathlib import Path
import stat
import sys


def integer(value, name, low=0, high=10**18):
    if type(value) is not int or not low <= value <= high:
        raise ValueError(name + ': expected an integer in the documented range')
    return value


def number(value, name, low=0, high=10**12):
    if type(value) not in (int, float) or not math.isfinite(value) or not low <= value <= high:
        raise ValueError(name + ': expected a finite number in the documented range')
    return value


def text(value, name):
    if not isinstance(value, str) or not value.strip() or len(value) > 1000:
        raise ValueError(name + ': expected nonempty bounded text')
    if any(ord(c) < 32 or ord(c) == 127 for c in value):
        raise ValueError(name + ': control characters are not allowed')
    return value


def fields(obj, names):
    if not isinstance(obj, dict) or set(obj) != set(names.split()):
        raise ValueError('expected exactly these fields: ' + names)


def reject_duplicates(pairs):
    result = {}
    for key, value in pairs:
        if key in result:
            raise ValueError('duplicate JSON key')
        result[key] = value
    return result


def load(path):
    # A private, trusted lab workspace is a prerequisite, not a hostile-directory sandbox.
    if path.is_symlink() or not stat.S_ISREG(path.stat().st_mode):
        raise ValueError('input must be a regular non-symlink file')
    with path.open('rb') as stream:
        data = stream.read(1024 * 1024 + 1)
    if len(data) > 1024 * 1024:
        raise ValueError('input exceeds the 1 MiB lab limit')
    return json.loads(data.decode('utf-8'), object_pairs_hook=reject_duplicates,
                      parse_constant=lambda _: (_ for _ in ()).throw(ValueError('nonfinite JSON value')))


def analyze(doc):
    fields(doc, 'before after elapsed_seconds')
    number(doc['elapsed_seconds'], 'elapsed_seconds', 0.001, 300)
    for key in ('before', 'after'):
        if not isinstance(doc[key], list) or len(doc[key]) != 8:
            raise ValueError(key + ': expected exactly eight CPU counters')
        for value in doc[key]:
            integer(value, key)
    delta = [new - old for old, new in zip(doc['before'], doc['after'])]
    if any(value < 0 for value in delta):
        raise ValueError('counter regression: collect a fresh comparable pair')
    total = sum(delta)
    if total == 0:
        raise ValueError('no accounted CPU interval')
    execution = sum(delta[index] for index in (0, 1, 2, 5, 6))
    def percent(ticks):
        return round(100 * ticks / total, 2)
    return int(execution / total >= 0.8), {
        'accounted_ticks': total, 'execution_percent': percent(execution),
        'idle_percent': percent(delta[3]), 'iowait_percent': percent(delta[4]),
        'steal_percent': percent(delta[7]), 'threshold': 'execution >= 80% (lab only)'}


def main():
    parser = argparse.ArgumentParser(description=__doc__)
    parser.add_argument('input', type=Path, help='private lab JSON evidence file; never executed as code')
    args = parser.parse_args()
    try:
        status, report = analyze(load(args.input))
        print(json.dumps(report, sort_keys=True, indent=2, allow_nan=False))
        return status
    except (OSError, ValueError, TypeError, KeyError, OverflowError, RecursionError) as error:
        print('ERROR: ' + str(error), file=sys.stderr)
        return 2


if __name__ == '__main__':
    sys.exit(main())
PY
```

## Explain the implementation

`fields` rejects missing and unexpected object fields so a misspelling cannot silently become an absent observation. `integer` rejects booleans as numeric counters. `number` rejects nonfinite values. Those checks are deliberate: Python otherwise treats `True` as an integer, and permissive JSON parsers may accept nonstandard numeric constants.

`load` bounds the input size before decoding it and rejects duplicate keys. The `analyze` function contains your subject-specific decisions; walk through it with the supplied numbers and predict the report before running it. `main` prints JSON rather than terminal control sequences and keeps errors on stderr. It does not open a second evidence file, invoke a repair command or change host policy.

Your program has no execute permission requirement because you invoke it explicitly with `python3`. That keeps the interpreter choice visible. Do not run it as root merely because an input is inaccessible.

# Part 10 — Create and run your regression suite

The tests launch the actual CLI in fresh subprocesses, compare selected report fields and check meaningful nonzero statuses. They also reject malformed, duplicate-key, nonfinite, missing, oversized, directory and symbolic-link inputs. Test fixtures are private and removed after the run.

```bash
cat > tests/run-tests.py <<'PY'
#!/usr/bin/env python3
"""Run the documented fixture checks without inspecting or changing a host."""
import json
from pathlib import Path
import subprocess
import sys
import tempfile

ROOT = Path(__file__).resolve().parents[1]
TOOL = ROOT / 'scripts' / 'cpu-interval.py'
CASES = [('normal CPU interval', {'before': [100, 0, 50, 800, 20, 0, 0, 10], 'after': [130, 0, 70, 930, 30, 0, 0, 20], 'elapsed_seconds': 1}, 0, {'execution_percent': 25.0, 'idle_percent': 65.0, 'iowait_percent': 5.0, 'steal_percent': 5.0}), ('execution attention', {'before': [100, 0, 50, 800, 20, 0, 0, 10], 'after': [290, 0, 50, 810, 20, 0, 0, 10], 'elapsed_seconds': 1}, 1, {'execution_percent': 95.0}), ('regressing counter', {'before': [100, 0, 50, 800, 20, 0, 0, 10], 'after': [99, 0, 70, 930, 30, 0, 0, 20], 'elapsed_seconds': 1}, 2, {}), ('zero accounted interval', {'before': [100, 0, 50, 800, 20, 0, 0, 10], 'after': [100, 0, 50, 800, 20, 0, 0, 10], 'elapsed_seconds': 1}, 2, {}), ('boolean counter', {'before': [True, 0, 50, 800, 20, 0, 0, 10], 'after': [130, 0, 70, 930, 30, 0, 0, 20], 'elapsed_seconds': 1}, 2, {}), ('zero elapsed time', {'before': [100, 0, 50, 800, 20, 0, 0, 10], 'after': [130, 0, 70, 930, 30, 0, 0, 20], 'elapsed_seconds': 0}, 2, {})]


def run(path):
    return subprocess.run([sys.executable, str(TOOL), str(path)],
                          capture_output=True, text=True, timeout=10)


def check(condition, message):
    if not condition:
        raise AssertionError(message)


count = 0
with tempfile.TemporaryDirectory(prefix='regression-', dir=ROOT / 'fixtures') as temp:
    folder = Path(temp)
    for name, document, status, expected in CASES:
        path = folder / 'case.json'
        path.write_text(json.dumps(document), encoding='utf-8')
        result = run(path)
        check(result.returncode == status, name + ': status: ' + result.stderr + result.stdout)
        if status != 2:
            report = json.loads(result.stdout)
            for key, value in expected.items():
                check(report.get(key) == value, name + ': unexpected ' + key + ': ' + result.stdout)
        else:
            check(not result.stdout and result.stderr.startswith('ERROR:'), name + ': error contract')
        print('PASS ' + name)
        count += 1
    for name, payload in [('bad-json', '{'), ('duplicate-key', '{"x":1,"x":2}'),
                          ('nonfinite', '{"x":NaN}'), ('invalid-utf8', b'\xff')]:
        path = folder / 'invalid.json'
        path.write_bytes(payload if isinstance(payload, bytes) else payload.encode('utf-8'))
        result = run(path)
        check(result.returncode == 2 and not result.stdout, name)
        print('PASS ' + name)
        count += 1
    missing = folder / 'missing.json'
    check(run(missing).returncode == 2, 'missing input')
    count += 1
    target = folder / 'target.json'
    target.write_text('{}', encoding='utf-8')
    link = folder / 'link.json'
    link.symlink_to(target)
    check(run(link).returncode == 2, 'symlink input')
    count += 1
    large = folder / 'large.json'
    large.write_bytes(b' ' * (1024 * 1024 + 1))
    check(run(large).returncode == 2, 'oversized input')
    count += 1
    check(run(folder).returncode == 2, 'directory input')
    count += 1
print('PASS: %s assertions; temporary test fixtures removed' % count)
PY
```

# Part 15 — Knowledge assessment

Answer these before reading the explanation. Demonstrate the answers with your own evidence where appropriate.

## 1. Why are two snapshots necessary?

The counters are cumulative. Their difference defines the interval that the percentage describes.

## 2. Why exclude guest fields from the sum?

Their time is included in user/nice accounting; adding them again double-counts that time.

## 3. Is load average CPU percent?

No. It describes a time-averaged queue-related quantity that includes uninterruptible tasks on Linux.

## 4. What is your execution numerator?

The user, nice, system, irq and softirq deltas, using all eight accounted deltas as the denominator.

## 5. Does I/O wait prove a particular disk is slow?

No. Its accounting has limitations and does not identify a device or application path.

## 6. What does steal suggest?

Time accounted to involuntary wait under the hypervisor; investigate the VM boundary rather than declaring the application defective.

## 7. Why reject a zero interval?

There is no accounted denominator for an interval percentage; returning zero utilization would invent a measurement.

## 8. Why retain actual elapsed time?

Scheduling can delay the collector, so a requested one-second sleep is not proof of an exact one-second sample.

## 9. Why can a process exceed 100%?

Some views normalize to one CPU; multiple executing threads can consume more than one CPU worth of time.

## 10. Does 25% aggregate CPU imply spare capacity for every workload?

No. A serial bottleneck or uneven CPU placement can coexist with idle CPUs.
