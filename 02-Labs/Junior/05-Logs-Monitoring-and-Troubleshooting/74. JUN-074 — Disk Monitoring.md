# Part 1 — Follow a path to the filesystem that serves it

An application writes to a path, not an abstract dashboard called “the disk.” A mount can change which filesystem serves that path, and a parent filesystem can differ from a nested mount. Begin with the exact failing path and its mount ownership.

On your Linux VM, use your workspace as the harmless target:

```bash
findmnt --target "$lab"
df -Pk -- "$lab"
df -Pi -- "$lab"
du -sk -- "$lab"
```

`df` asks the filesystem for capacity. `du` walks directory entries and estimates allocated storage it can observe. They have different scope, access and timing, so their numbers need not match. A whole-root `du` scan can be expensive and cross operational boundaries; your exercise stays in the small workspace.

Record mount source, filesystem type and the exact path. A container overlay, network filesystem, quota or deleted-open file can complicate interpretation; this lab does not turn a single percentage into a diagnosis of those cases.

# Part 2 — Separate free blocks from available blocks

Filesystem interfaces distinguish total blocks, free blocks and blocks available to an ordinary user. Reserved space can make available smaller than free. Do not label their difference as a leak or remove a reservation to make a graph look better.

The lab model reports ordinary-user unavailability as `(total − available) / total`. This is deliberately named unavailability rather than a byte-for-byte copy of GNU df's displayed Use% formula. It includes unavailable reserve as well as occupied capacity. The tool also reports `free − available` so that you retain the distinction.

Use block counts in one consistent allocation unit; convert to bytes only when you also retain the block size. Mixing df KiB output with raw statvfs blocks would change the denominator silently.

# Part 3 — Recognize inode exhaustion

Many filesystems limit metadata objects separately from data blocks. Small files can exhaust available inodes while substantial byte capacity remains. A create operation may then fail with a space-related error even though the byte chart looks comfortable.

A zero inode total can mean this interface does not provide a useful inode limit. Your tool marks that part unknown and returns attention rather than dividing by zero or declaring it healthy. Filesystem-specific metadata, user/project quotas and remote server limits still need their own observations.

Do not create millions of files or fill a real mount for this lab. You will model the boundary with a few JSON values and later investigate a bounded disk-space incident in JUN-081.

# Part 7 — Design the final tool before typing it

Your tool accepts one JSON evidence file. It reads at most 1 MiB, rejects malformed JSON, duplicate keys, nonfinite numbers, directories and final-component symbolic links, and validates the domain fields before printing a report. It never evaluates the input as shell or Python code.

| Exit status | Meaning |
| --- | --- |
| 0 | The documented analysis completed and its success criterion is met |
| 1 | Valid evidence requires attention, or the available evidence cannot establish the required outcome |
| 2 | Input, schema, range, collection or usage error; no normal report is printed |

A zero result concerns this tool's stated contract, not whole-system health. An attention result is different from malformed input. Your shell's status must be captured immediately after the command, before another command replaces it.

The tool evaluates blocks and inodes independently, using explicitly named lab thresholds. It rejects impossible ordering, preserves reserve and treats unavailable inode accounting as unknown. It is not a replacement for df, quotas or filesystem-specific tooling.

The file checks assume your private workspace is trusted. They are not race-proof protection against a malicious writer changing parent directories or files during a read. Do not expose the tool as a privileged service or point it at hostile paths.

# Part 8 — Implement your tool

<!-- lab:implementation -->
```bash
cat > scripts/disk-headroom.py <<'PY'
#!/usr/bin/env python3
"""Disk Monitoring — bounded evidence analysis for this lab."""
import argparse
import datetime as dt
import json
import math
from pathlib import Path
import stat
import sys


def integer(value, name, low=0, high=10**18):
    if type(value) is not int or not low <= value <= high:
        raise ValueError(name + ': expected an integer in the documented range')
    return value


def number(value, name, low=0, high=10**12):
    if type(value) not in (int, float) or not math.isfinite(value) or not low <= value <= high:
        raise ValueError(name + ': expected a finite number in the documented range')
    return value


def text(value, name):
    if not isinstance(value, str) or not value.strip() or len(value) > 1000:
        raise ValueError(name + ': expected nonempty bounded text')
    if any(ord(c) < 32 or ord(c) == 127 for c in value):
        raise ValueError(name + ': control characters are not allowed')
    return value


def fields(obj, names):
    if not isinstance(obj, dict) or set(obj) != set(names.split()):
        raise ValueError('expected exactly these fields: ' + names)


def reject_duplicates(pairs):
    result = {}
    for key, value in pairs:
        if key in result:
            raise ValueError('duplicate JSON key')
        result[key] = value
    return result


def load(path):
    # A private, trusted lab workspace is a prerequisite, not a hostile-directory sandbox.
    if path.is_symlink() or not stat.S_ISREG(path.stat().st_mode):
        raise ValueError('input must be a regular non-symlink file')
    with path.open('rb') as stream:
        data = stream.read(1024 * 1024 + 1)
    if len(data) > 1024 * 1024:
        raise ValueError('input exceeds the 1 MiB lab limit')
    return json.loads(data.decode('utf-8'), object_pairs_hook=reject_duplicates,
                      parse_constant=lambda _: (_ for _ in ()).throw(ValueError('nonfinite JSON value')))


def analyze(doc):
    fields(doc, 'blocks_total blocks_free blocks_available inodes_total inodes_available')
    for key, value in doc.items():
        integer(value, key)
    total, free, available = (doc[k] for k in ('blocks_total', 'blocks_free', 'blocks_available'))
    if not 0 <= available <= free <= total or total == 0:
        raise ValueError('require 0 <= available <= free <= positive total blocks')
    inode_total, inode_available = doc['inodes_total'], doc['inodes_available']
    if inode_available > inode_total:
        raise ValueError('available inodes exceed total')
    block_alert = (total - available) * 10 >= total * 9
    unknown = inode_total == 0
    inode_alert = not unknown and (inode_total - inode_available) * 10 >= inode_total * 9
    return int(block_alert or inode_alert or unknown), {
        'block_unavailable_percent': round(100 * (total - available) / total, 2),
        'unavailable_reserve_blocks': free - available,
        'inode_unavailable_percent': None if unknown else round(100 * (inode_total - inode_available) / inode_total, 2),
        'block_attention': block_alert, 'inode_attention': inode_alert,
        'inode_state': 'unknown' if unknown else 'measured'}


def main():
    parser = argparse.ArgumentParser(description=__doc__)
    parser.add_argument('input', type=Path, help='private lab JSON evidence file; never executed as code')
    args = parser.parse_args()
    try:
        status, report = analyze(load(args.input))
        print(json.dumps(report, sort_keys=True, indent=2, allow_nan=False))
        return status
    except (OSError, ValueError, TypeError, KeyError, OverflowError, RecursionError) as error:
        print('ERROR: ' + str(error), file=sys.stderr)
        return 2


if __name__ == '__main__':
    sys.exit(main())
PY
```

## Explain the implementation

`fields` rejects missing and unexpected object fields so a misspelling cannot silently become an absent observation. `integer` rejects booleans as numeric counters. `number` rejects nonfinite values. Those checks are deliberate: Python otherwise treats `True` as an integer, and permissive JSON parsers may accept nonstandard numeric constants.

`load` bounds the input size before decoding it and rejects duplicate keys. The `analyze` function contains your subject-specific decisions; walk through it with the supplied numbers and predict the report before running it. `main` prints JSON rather than terminal control sequences and keeps errors on stderr. It does not open a second evidence file, invoke a repair command or change host policy.

Your program has no execute permission requirement because you invoke it explicitly with `python3`. That keeps the interpreter choice visible. Do not run it as root merely because an input is inaccessible.

# Part 10 — Create and run your regression suite

The tests launch the actual CLI in fresh subprocesses, compare selected report fields and check meaningful nonzero statuses. They also reject malformed, duplicate-key, nonfinite, missing, oversized, directory and symbolic-link inputs. Test fixtures are private and removed after the run.

<!-- lab:tests -->
```bash
cat > tests/run-tests.py <<'PY'
#!/usr/bin/env python3
"""Run the documented fixture checks without inspecting or changing a host."""
import json
from pathlib import Path
import subprocess
import sys
import tempfile

ROOT = Path(__file__).resolve().parents[1]
TOOL = ROOT / 'scripts' / 'disk-headroom.py'
CASES = [('normal filesystem snapshot', {'blocks_total': 1000, 'blocks_free': 400, 'blocks_available': 300, 'inodes_total': 100, 'inodes_available': 50}, 0, {'block_unavailable_percent': 70.0, 'unavailable_reserve_blocks': 100, 'inode_unavailable_percent': 50.0}), ('block threshold', {'blocks_total': 1000, 'blocks_free': 400, 'blocks_available': 100, 'inodes_total': 100, 'inodes_available': 50}, 1, {'block_attention': True}), ('inode threshold', {'blocks_total': 1000, 'blocks_free': 400, 'blocks_available': 300, 'inodes_total': 100, 'inodes_available': 10}, 1, {'inode_attention': True}), ('unknown inode accounting', {'blocks_total': 1000, 'blocks_free': 400, 'blocks_available': 300, 'inodes_total': 0, 'inodes_available': 0}, 1, {'inode_state': 'unknown', 'inode_unavailable_percent': None}), ('available exceeds free', {'blocks_total': 1000, 'blocks_free': 400, 'blocks_available': 401, 'inodes_total': 100, 'inodes_available': 50}, 2, {}), ('zero block capacity', {'blocks_total': 0, 'blocks_free': 400, 'blocks_available': 300, 'inodes_total': 100, 'inodes_available': 50}, 2, {})]


def run(path):
    return subprocess.run([sys.executable, str(TOOL), str(path)],
                          capture_output=True, text=True, timeout=10)


def check(condition, message):
    if not condition:
        raise AssertionError(message)


count = 0
with tempfile.TemporaryDirectory(prefix='regression-', dir=ROOT / 'fixtures') as temp:
    folder = Path(temp)
    for name, document, status, expected in CASES:
        path = folder / 'case.json'
        path.write_text(json.dumps(document), encoding='utf-8')
        result = run(path)
        check(result.returncode == status, name + ': status: ' + result.stderr + result.stdout)
        if status != 2:
            report = json.loads(result.stdout)
            for key, value in expected.items():
                check(report.get(key) == value, name + ': unexpected ' + key + ': ' + result.stdout)
        else:
            check(not result.stdout and result.stderr.startswith('ERROR:'), name + ': error contract')
        print('PASS ' + name)
        count += 1
    for name, payload in [('bad-json', '{'), ('duplicate-key', '{"x":1,"x":2}'),
                          ('nonfinite', '{"x":NaN}'), ('invalid-utf8', b'\xff')]:
        path = folder / 'invalid.json'
        path.write_bytes(payload if isinstance(payload, bytes) else payload.encode('utf-8'))
        result = run(path)
        check(result.returncode == 2 and not result.stdout, name)
        print('PASS ' + name)
        count += 1
    missing = folder / 'missing.json'
    check(run(missing).returncode == 2, 'missing input')
    count += 1
    target = folder / 'target.json'
    target.write_text('{}', encoding='utf-8')
    link = folder / 'link.json'
    link.symlink_to(target)
    check(run(link).returncode == 2, 'symlink input')
    count += 1
    large = folder / 'large.json'
    large.write_bytes(b' ' * (1024 * 1024 + 1))
    check(run(large).returncode == 2, 'oversized input')
    count += 1
    check(run(folder).returncode == 2, 'directory input')
    count += 1
print('PASS: %s assertions; temporary test fixtures removed' % count)
PY
```

# Part 15 — Knowledge assessment

Answer these before reading the explanation. Demonstrate the answers with your own evidence where appropriate.

## 1. Why start with findmnt for the path?

It identifies the mount that actually serves the target rather than an assumed device.

## 2. Why can df and du differ?

One reports filesystem capacity, while the other walks visible entries; scope, metadata, open files and timing differ.

## 3. Is available space identical to free space?

No. Ordinary-user availability can exclude reserved capacity.

## 4. Does the report exactly reproduce df Use%?

No. It explicitly uses total-minus-available divided by total, which includes unavailable reserve.

## 5. Why monitor inodes separately?

Metadata capacity can be exhausted even when blocks remain available.

## 6. What does zero inode total mean here?

Unknown inode capacity in this contract; the tool does not infer healthy usage.

## 7. Can this snapshot diagnose a quota?

No. User/project quotas need separate scope and interfaces.

## 8. Why avoid a full-root du scan in this exercise?

It can be costly, denied or cross unrelated data and mounts; the small workspace is the intended boundary.

## 9. What is the normal unavailable reserve?

400 free minus 300 available equals 100 blocks.

## 10. Why use fixtures for exhaustion?

They make the decision reproducible without filling the filesystem that your machine needs to operate.
