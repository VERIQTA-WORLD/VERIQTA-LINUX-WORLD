## Curation standard

Each future entry should explain when it is useful, its intended reader, prerequisites, relevant version/distribution scope, source authority and review date. Distinguish upstream behavior from packaged defaults. Prefer primary documentation for technical claims and preserve third-party licenses rather than copying their content wholesale.

A glossary definition should connect to an example. A configuration path should explain who owns it and how changes become effective. A log path should identify alternatives and access/retention limitations. Review links and claims over time; do not imply that one path or default applies to every Linux installation.
