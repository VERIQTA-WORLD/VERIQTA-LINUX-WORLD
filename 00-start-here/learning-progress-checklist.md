# Learning progress and evidence checklist

Track what you can demonstrate, not only what you have read. Use one record per topic, exercise or project and distinguish guided work from independent work.

## Progress states

| State | Evidence |
| --- | --- |
| Read | Explain the concept, prerequisites and likely effects in your own words |
| Followed | Complete the documented exercise and retain actual observations/cleanup |
| Reproduced | Repeat from its stated prerequisites without hidden setup or copied assumptions |
| Extended | Make one independent change, predict its effect, verify it and explain the trade-off |

## Record template

```text
Goal and topic:
Page and repository revision:
Environment: OS/release, architecture, tool versions, account/permissions:
Prerequisites confirmed:
Expected behavior:
Actual observations and meaningful exit statuses:
What failed, why, and what evidence supports that explanation:
Verification of the intended outcome:
Cleanup/recovery completed:
What remains untested or uncertain:
Independent extension and result:
Next learning step:
```

## Foundation checkpoints

- [ ] Navigate paths and handle spaces without changing unintended targets.
- [ ] Create, inspect, search, compare and remove temporary data safely.
- [ ] Explain identity, ordinary permissions and additional policy boundaries.
- [ ] Distinguish process state, service state and application readiness.
- [ ] Separate name resolution, network connection and application response failures.
- [ ] Identify a path's filesystem, capacity and relevant scope before acting.
- [ ] Reject an invalid candidate and rehearse a verified rollback/restore.
- [ ] State what your experiment proves and what it does not establish.

Complete only the relevant checkpoints for your current route. A checked list does not certify job seniority, production experience or readiness to change someone else's system.
