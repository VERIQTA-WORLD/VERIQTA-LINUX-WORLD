## Learn through practice and evidence

Understand the concept, inspect what the tool reads or changes, practise in isolation, verify the result and explain the evidence. Where appropriate, progress toward automation, a controlled failure and recovery. Use explicit prerequisites and meaningful acceptance checks rather than treating a command's exit status as proof the whole system is healthy.

- [Lessons](01-Beginner-to-Advanced), [labs](02-Labs) and [projects](03-Projects) connect concepts to practical work.
- [Command validation](04-command-reference/VALIDATION.md), [recovery validation](05-troubleshooting-and-recovery/VALIDATION.md), [administration validation](06-system-administration/VALIDATION.md) and [distribution validation](07-linux-distributions/VALIDATION.md) record execution environments, checks and platform-specific limits.
- [Content standard](CONTENT-STANDARD.md) defines expectations for explanation, scope, practice and recovery.
- [Repository structure and migration](docs/repository-structure.md) maps collection paths and navigation changes.
